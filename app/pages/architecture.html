Architecture et registre

D'où viennent les données, quels modèles existent, lequel est en production et comment il se comporte. Tout est lu dans le manifeste des données, le registre de modèles et les rapports de suivi.

Chaîne de traitement

sources → ingestion → imputation et contrôles → variables → entraînement → évaluation → registre → API et application → suivi

Chaque étape est une commande de python -m solarvision.cli. Le schéma détaillé est dans docs/architecture.md.

Ce qui n'est pas fait

  • Tout tourne sur une machine locale : pas de stockage distant ni de déploiement dans le nuage.
  • Pas de réentraînement automatique : une dérive est signalée, la décision reste humaine.
  • Le suivi est recalculé à la demande, il n'envoie aucune alerte.
